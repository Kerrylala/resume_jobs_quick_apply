# Resume Jobs AI 中文开发架构

## 架构原则

Resume Jobs 是现有的 local-first 单用户产品，不是多套 Agent 实验的集合。
开发必须复用 Dashboard、领域契约、Workflow State、Application Package 和
Chrome 扩展，不能创建平行实现。

## 主要模块

```text
dashboard/server.mjs              本地 HTTP API、静态页面与 Workflow 编排
dashboard/public/                 七个产品区域的 UI
scripts/lib/                      领域逻辑与共享持久化
scripts/discover_jobs.mjs         公开职位发现与统一标准化
scripts/score_jobs.mjs            确定性评分与候选人六维匹配
scripts/build_application_package_preview.mjs
                                  Application Package 构建
providers/                        搜索、ATS 检测与公开页面解析
extensions/application_assistant/    唯一浏览器自动填写实现
mock_sites/                       localhost ATS 合成测试站
tests/                            离线单元、API、浏览器和 E2E 测试
```

## 核心数据流

```text
Resume file
  -> Resume Library/version/hash
  -> Resume Intelligence facts (review required)
  -> approved Candidate Profile snapshot
  -> Search Preferences + Search Provider/User URL
  -> normalized job_leads
  -> candidate-aware jobs_shortlist
  -> explicit job approval
  -> Application Package + completion plan
  -> ApplicationExecutionSession
  -> Extension / Local Browser Agent safe fill report
  -> NEEDS_USER_INPUT / READY_FOR_MANUAL_SUBMIT
  -> user submits manually
```

## Workflow State

`scripts/lib/workflow_state.mjs` 只根据当前领域记录计算：

- Resume 是否存在；
- Candidate Profile 当前快照是否批准；
- 当前 Search Configuration 是否保存；
- 同一配置指纹是否完成搜索；
- 是否存在当前已评分/已批准职位；
- Package、Fill、Review 和手工提交状态。

浏览器缓存、Demo 标志和旧报告不能推进 Workflow。

## AI Provider

所有模型任务通过 `scripts/lib/ai_provider.mjs`。支持 disabled、local
OpenAI-compatible、OpenAI、Anthropic 和通用 OpenAI-compatible。模型输出
只能提供解释或建议，不能修改确定性评分、批准状态、浏览器安全策略和
Application State。详情见根目录 `AI_PROVIDER.md`。

## 持久化

当前使用本地 JSON。Dashboard、发现、评分和 AI enrichment 的关键写入
通过 `scripts/lib/json_repository.mjs` 执行同目录临时文件 + fsync + rename
原子替换。正式数据、个人 Profile、简历、API key、浏览器 profile、运行
报告和本地扩展 bundle 必须被 Git 排除。

## 浏览器边界

扩展使用 Manifest V3。自动 host 范围只包括 localhost、Greenhouse、Lever、
Ashby 和 Workday；其他页面需要用户打开 popup 后使用 `activeTab`。Dashboard 的
private handoff 要求扩展 origin、active Application Session 和 URL 匹配。详情见
根目录 `EXTENSION_ARCHITECTURE.md`。

## 测试策略

```powershell
npm run validate
npm test
npm run test:e2e
npm run test:browser
npm run test:browser:headed
npm run test:launcher
```

默认测试通过 preload guard 禁止外网和项目内写入；所有变更数据写系统临时
目录。浏览器测试使用 Playwright Core 驱动已安装的 Chrome/Edge，并由 CDP
完成完整安全契约；`test:browser:headed` 提供可见模式。测试只访问 localhost，
使用临时 profile，并断言不提交、不上传、不登录。

## 开发规则

1. 修改前检查 `git status`，保留无关用户修改。
2. 一次完成一个明确产品任务。
3. UI 禁止浏览器原生 `alert`、`confirm`、`prompt`。
4. 真实网站、登录、上传简历和真实投递必须获得明确授权。
5. 修改后先跑最小测试，再跑 `npm test`。
6. 更新 `docs/DEVELOPMENT_LOG.md`。
