# Resume Jobs AI 中文故障排查

## 启动失败

### 提示缺少 Node.js

安装 Node.js 18+，重新打开 PowerShell，执行：

```powershell
node --version
npm --version
```

### 8767 端口被占用

先确认是否已有 Resume Jobs 在运行。不要强制结束未知进程。可执行：

```powershell
Get-NetTCPConnection -LocalPort 8767 -ErrorAction SilentlyContinue
```

如确实是本项目启动的服务，运行
`scripts\stop_dashboard_windows.ps1` 后重试。

## Dashboard 打不开或数据为空

1. 确认地址是 `http://127.0.0.1:8767`。
2. 执行 `npm run validate`。
3. 检查 Dashboard 是否明确提示 Resume、Profile 或 Search 尚未完成。
4. 不要通过手改 JSON 跳过 Workflow。

首次空目录出现空列表是正常状态；上传 Resume 后应进入 Review Profile。

## Resume 上传或解析失败

- 只支持 PDF、DOCX、UTF-8 TXT。
- 文件上限为 10 MB。
- 加密 PDF、扫描图片 PDF 或复杂字体 PDF 可能没有可提取文本。
- TXT 必须是 UTF-8 且不能包含二进制/NUL 数据。
- 上传成功但解析失败时，Resume Version 仍会保留，可换 DOCX/TXT 后重试。

系统不会把原始简历文本写入 Candidate Facts，也不会在解析时调用模型。

## Profile 无法批准

检查：

- 当前 active Resume 文件是否仍存在且 hash 一致；
- 是否已经审阅当前事实快照；
- Resume 或事实是否在批准后发生变化；
- 是否存在待处理冲突或缺失的核心事实。

修改 Resume 或 Profile 会主动撤销旧批准，这是安全设计。

## Live Search 无结果

1. 在 **Settings -> Job Search Sources** 启用 SearXNG。
2. 保存 endpoint，并点击 **Test Connection**。
3. 确认状态为 `READY`。
4. 确认 Job Search 已保存至少一个 target role。

如果 provider 未配置，使用“导入公开职位 URL”或 Offline Demo。系统不会
在 provider 缺失时假装搜索成功。

## 公开职位 URL 导入失败

- 必须是 HTTP/HTTPS URL；远程站点必须使用 HTTPS。
- URL 不能包含用户名或密码。
- 不允许内网、链路本地、非标准远程端口或重定向目标。
- 页面必须返回大小受限的 HTML/text，并包含可识别职位标题。
- 使用职位详情页，不要使用登录页、搜索结果页或申请提交页。

## AI Provider 不可用

- AI 被禁用不会阻止搜索、评分和 Workflow。
- 本地 provider 只能使用 localhost/loopback。
- OpenAI/Anthropic 需要 API key；远程 endpoint 必须是 HTTPS。
- 修改设置后先 Save，再 Test Connection。
- API key 不会显示在 GET Settings 或日志中。

## 扩展无法自动填写

1. 确认扩展已加载并刷新。
2. Dashboard 中先完成 Approve AI Fill 和 Start AI Fill Assistant。
3. 在完全匹配的职位页面打开 popup。
4. 确认扩展弹窗显示“已连接”“已找到申请”和“申请包已就绪”。
5. 对非 Greenhouse/Lever/Workday 页面，必须由用户打开 popup 触发
   `activeTab` 注入。
6. 真实站点 Profile 必须明确批准 real-site autofill；否则扩展会阻止。

登录、CAPTCHA、MFA、未知问题、敏感问题、文件附件和最终 Submit 被阻止
是正常安全行为，不是故障。

## 测试失败

```powershell
npm run validate
npm test
npm run test:e2e
npm run test:launcher
```

浏览器 E2E 需要本机 Chrome 或 Edge；它只使用临时 profile 和 localhost。
不要用正式个人数据修改测试夹具。若仍失败，保留终端输出，并记录 Node
版本、浏览器路径和失败测试名称到 `docs/DEVELOPMENT_LOG.md`。
