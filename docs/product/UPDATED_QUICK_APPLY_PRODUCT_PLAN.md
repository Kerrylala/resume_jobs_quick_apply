## 1. 产品定位

**Resume Jobs 是一个简单的 AI 求职申请助手，不是 Career OS。**

一句话：上传一次简历，之后每个岗位都只差一个「用 AI 申请」按钮，就能把申请页面安全地填好交回给你。

用户脑子里只有四个名词：**我的资料、岗位、申请、我的答案**。Package、Session、Executor、状态机常量、评分 JSON、完成度百分比，全部是产品自己的事，永远不出现在默认界面。

### 默认流程

```
上传简历
  → 快速生成并完善在线求职档案
  → 导入岗位链接 或 自动搜索岗位
  → 点击「用 AI 申请」
  → 准备申请资料
  → 按需生成岗位定制简历
  → 按需生成求职信
  → 打开申请页面并填写
  → 用户处理剩余内容
  → 用户确认或提交
```

### 目标用户

正在找工作、可能有压力、可能不懂技术、母语中文。不会读文档。每一屏只问一个问题：**我现在该做什么？** 只有在产品从不在浏览器里做出意外动作、并且从不谎报自己做了什么的前提下，才会信任它。

## 2. 在线求职档案

**在线求职档案是唯一数据源。**

上传 PDF/DOCX 的作用只是快速生成或更新在线档案。之后所有功能都只从在线档案取数据：

- 岗位匹配
- 网页填写
- 定制简历
- 求职信
- 常见申请答案

### 档案分区

| 分区 | 内容 |
|---|---|
| 基本信息 | 姓名（含中文名/英文名）、邮箱、电话、所在城市/省/国家、LinkedIn、GitHub、作品集 |
| 求职意向 | 目标岗位、目标国家/城市、行业偏好、排除行业、远程偏好、薪资期望 |
| 工作情况 | 当前公司、工作许可、是否需要签证担保、是否接受搬迁、最早到岗日期、离职通知期 |
| 教育经历 | 学校、学位、专业、时间、成绩与课程 |
| 工作经历 | 公司、职位、时间、职责、成果、技术栈 |
| 项目经历 | 名称、描述、技术、成果、链接 |
| 技能 | 编程、AI 工具、框架、云、数据、业务（六组） |
| 证书与语言 | 证书、语言及熟练度 |
| 我的答案 | 已保存的申请问答 |
| 我的简历文件 | 上传的原始简历（可多份、有版本） |
| 岗位定制材料 | 每个岗位的定制简历与求职信 |

### 字段徽标

每个可用于填表的字段只有两种状态，界面上直接显示：

- `自动填写` — 已确认，申请时会自动填进表单
- `每次询问` — 敏感或政策类字段（工作许可、签证担保、薪资、搬迁、到岗时间、离职通知期），存下来但每次申请前问一次

### 上传新简历

上传新简历会替换当前的解析来源，但：

1. 先展示解析结果，问一次「用这些内容更新你的资料吗？」
2. 确认后创建**新版本**，旧版本完整保留
3. 界面上保留一个明确的「撤销，回到 <日期> 的版本」入口

**产品从不凭空编造事实。** 简历里没有的内容，档案里就留空，界面上显示「未填写」，不会用推测值填上。

## 3. 数据管理

普通用户只需要管理六样东西：在线求职档案、上传的原始简历、岗位定制简历、求职信、已保存申请答案、申请记录。

### 两个明确操作

**① 清除求职资料**

删除：简历文件、在线档案、定制简历、求职信、已保存答案、表单字段记忆、学习候选、申请准备文件、相关缓存。

**保留：申请记录。**（你申请过哪些岗位、什么时候申请的、结果如何，不会因为清资料而消失。）

**② 删除全部用户数据**

删除所有个人资料、岗位、申请、搜索、AI 配置和运行数据。产品回到刚安装的状态。

### 两者共同的规则

- 用产品自己的确认弹窗，不用浏览器原生对话框
- 执行前写一份带时间戳的备份到 `archive/`
- 明确列出「会删什么」和「不会删什么」
- 浏览器扩展在下次打开时自动跟随清空

### 隐私不变量（任何阶段都不放宽）

- API Key 只写在本机私有配置文件里（权限 0600），永不回传给界面、不进日志、不进截图、不进扩展包、不进 Git
- 简历原文从不落盘，只保留解析出来的结构化事实
- 所有截图都注入 CSS 把输入框文字变透明，截图里看不到你填了什么
- 学习候选在确认后清空原值，只留字段签名
- 全部数据留在你自己的电脑上

## 4. 岗位发现

四层，按可靠性排序。**下层出问题绝不阻塞上层。**

### 第 1 层 · 粘贴岗位链接（首次运行的默认路径）

你把一个岗位链接贴进来，产品抓取公开页面，提取公司、职位、地点、描述和申请链接。

- 不需要 AI
- 不需要配置搜索
- 不跟随重定向、拒绝私网地址、限制 1 MB、12 秒超时

这是唯一必然可用的路径，因此它是首页的第一个输入框。

### 第 2 层 · 公司官网招聘页

你给一个公司的 careers 页地址，产品抓出这个页面上的职位链接列表（最多 100 条），你勾选想要的导入。

产品**不做**「给公司名自动找官网」——那需要搜索引擎，属于第 3 层。

### 第 3 层 · SearXNG 搜索（可选）

SearXNG 是可选搜索来源，默认关闭。

- 设置页里明说：**没有它，产品照样能用**
- 搜索失败时如实说明「搜索源不可用」，不编造岗位、不写坏已有数据、不卡住任何流程
- 从不假装搜到了东西

### 第 4 层 · 国内招聘平台（辅助浏览）

BOSS直聘、拉勾、猎聘、智联招聘、前程无忧等平台需要登录且有反爬保护。产品对它们只做一件事：**打开页面，并排显示你的资料供复制。**

不抓取、不代替你登录、不绕过反爬。产品文档不会宣称支持国内平台的自动发现。

### 没有 AI 时仍然可用

搜索岗位 · 导入岗位链接 · 规则匹配（完全确定性的评分）· 打开申请页面 · 填写基本资料。

需要 AI 的功能会在界面上明确标出：语义匹配增强、定制简历、求职信。

## 5. AI 配置

### 默认优先检测本地

产品启动和打开设置页时，自动检测 `http://127.0.0.1:1234/v1`（LM Studio 默认地址），成功就自动读取已加载的模型并预填表单。检测失败静默处理，不弹错误。

### 支持的提供方

```
LM Studio (本地)     http://127.0.0.1:1234/v1
Ollama (本地)        http://127.0.0.1:11434/v1
vLLM / 其它本地       用户填写（必须是 loopback 地址）
OpenAI               https://api.openai.com/v1
Anthropic Claude     https://api.anthropic.com/v1
Google Gemini        https://generativelanguage.googleapis.com/v1beta/openai/
通用 OpenAI 兼容      用户填写（必须 HTTPS）
不使用 AI             全部功能走确定性路径
```

### 配置表单固定六项

```
Provider
API Key
Endpoint
Model        （下拉自动填充，也可自由输入）
测试连接
保存
```

API Key 留空 = 保留已保存的；勾选「移除已保存的 Key」= 清除。Key 只保存在本机私有配置中，不进 Git、日志或截图。

## 6. Quick Apply

普通界面中，每个岗位卡片只有一个主按钮：

```
用 AI 申请
```

（次要链接：`手动申请` — 只打开页面，不做任何填写。）

点击后系统内部自动处理：岗位批准、申请准备、简历选择、已知答案、浏览器代理、页面填写。

**硬预算：页面被填好之前最多 3 个决定。**

1. 确认/调整简历
2. 回答缺失的问题
3. 点「打开并填写」

其它一切要么自动，要么推后。

普通用户不应看到：Package · Session · Executor · Approve AI Fill · 内部状态名 · 内部 ID · 十步流程条。

### 用户看到的全部状态词表

```
已找到 · 准备中 · 填写中 · 需要你（N 项）· 可以提交了 · 已申请 · 已保存 · 已拒绝
```

### 旧 Dashboard

完整保留为「高级模式」，从默认界面只有菜单里一个入口能进去。诊断、原始 JSON、内部 ID、执行器手动选择、状态历史、审计事件都在那里。

## 7. 定制简历和求职信

### 定制简历不自动生成

用户点击「生成岗位定制简历」之后才调用 AI。

规则：

- **只使用在线档案中已确认的事实**，不虚构经历或技能
- 生成结果的每一条内容都必须能追溯到档案里的具体事实；追溯不上的整批丢弃，并告诉用户「AI 生成了无法核实的内容，已丢弃」
- 显示修改差异（改写了什么、重排了什么、补充了哪些关键词）
- 允许 `接受` / `编辑` / `继续使用原简历`
- 输出 DOCX 和 PDF
- 保存为岗位专属版本，可删除
- **原始简历永不修改**

### 求职信

同样只在用户点击后生成，可编辑、可不使用、**不阻塞申请**。

## 8. 文件上传和最终提交

### 简历上传设置

```
从不自动上传
每次询问          ← 默认
支持的网站自动上传
```

### 最终提交设置

```
永远手动提交              ← 默认
每个岗位单独询问是否自动提交
```

自动化只在本地浏览器代理模式下可用（Chrome 扩展模式无法重新扫描页面，无法在提交前验证状态，因此不参与自动化）。

### 硬停条件

即使用户已授权自动提交，遇到以下任一情况必须立即停止、切回手动、并在界面上说明原因：

1. 出现 CAPTCHA / 人机验证
2. 需要登录或多因素验证
3. 仍有必填项为空
4. 存在未经用户确认的敏感 / EEO / 身份类答案
5. 需要的文件缺失或附加失败
6. 页面不受支持 / 表单不可访问
7. 当前 URL 与已批准的申请 URL 不一致
8. 该岗位已经提交过（幂等保护）

### 三条不动的红线

| 红线 | 理由 |
|---|---|
| 不绕过、不代答人机验证 | 这是绕过站点的访问控制 |
| 不代替你登录、不代你输入 MFA 验证码 | 同上，且涉及你的账号凭据 |
| 不代答 EEO / 身份 / 医疗 / 法律声明类问题 | 这是替你做法律声明 |

这三条也正是上面硬停条件的第 1、2、4 项 —— 它们不是保守，是产品必须守住的边界。

### 如实报告

产品可以自动上传、可以自动提交，但**绝不能谎报自己做了什么**。执行报告必须如实记录：是否附加了文件、是否点了提交、结果是什么。任何一次自动提交都会写进申请记录和审计日志。

## 9. 答案记忆

所有用户确认过的申请答案都可以保存并复用。

在「我的答案」里，用户可以：查看 · 修改 · 删除 · 设置适用范围（全局 / 按公司 / 按岗位类型 / 按国家）· 查看使用记录（什么时候、在哪个申请里用过）。

### 保存的两条路径

1. **申请前就地保存** — 预备抽屉里问缺失的问题，带「记住这个答案」勾选框
2. **填完页面后学习** — 你在页面上手动输入的内容，产品重新扫描后逐条问「你在『X』里填了『Y』，下次要自动用吗？」，明确的是/否，绝不自动保存

### 敏感内容的额外限制

法律声明、EEO、身份、医疗等敏感问题即使存了答案，也**永远标记为「每次询问」**，不会自动填入，每次申请前单独确认一次。高风险项需要二次确认。

## 10. 界面

默认中文，可切换英文。

**默认导航（5 项）**

```
首页        一个推荐的下一步动作 + 最近活动
岗位        新发现 · 好匹配 · 已保存 · 已申请 · 已拒绝 + 添加岗位链接
申请        进行中的申请卡片，每张带「还差 N 项」清单
我的资料    在线求职档案 · 我的简历 · 我的答案 · 定制材料
设置        AI 配置 · 岗位来源 · 数据与隐私 · 语言
```

**二级入口（菜单，不是标签页）**

```
职业工具    面试题准备 · STAR 故事 · 技能差距分析
高级模式    当前 Dashboard（诊断、原始数据、执行器覆盖、内部 ID）
```

面试题、STAR 故事、技能差距**不出现在申请主流程中**。

### 界面规则

- 任何地方都没有步骤编号
- 没有任何一个视图是其它视图的堆叠
- 每个列表都分页
- 高级模式之外不渲染原始 JSON
- 不使用浏览器原生 `alert` / `confirm` / `prompt`
- 任何被禁用的控件必须在旁边的**可见文字**里说明原因，不能只靠置灰或 tooltip
- 完成一个动作不会把用户传送到另一个筛选、标签页或滚动位置

## 11. 六条产品承诺

这六句话出现在首次运行页面，并在一个常驻的「它绝不会做什么」链接后面：

1. 绝不绕过人机验证，绝不代替你登录或输入验证码。
2. 绝不代你回答 EEO、身份、医疗或法律声明类问题。
3. 上传文件和提交申请只在你明确授权后进行，默认都是你自己来。
4. 遇到任何拿不准的情况就停下来问你，不猜。
5. 绝不保存你没有确认过的答案。
6. 一切都在你自己的电脑上运行和保存。

## 12. 旧功能去向

### 移到高级模式（代码不动）

整个现有 Dashboard：诊断面板、原始 JSON、内部 ID 与摘要行、执行器手动选择、状态历史、Career Brain 原始编辑器、提供方健康检查、扩展诊断、审计事件。

死代码渲染器 · 两个无人读写的岗位状态文件 · 重复的答案序列化字段 · 重复的简历 ID 键 · 假的简历置信度查找表。
