## 1. 导航结构

```
┌─ 顶栏 ──────────────────────────────────────────────┐
│  Resume Jobs        首页 岗位 申请 我的资料 设置    ⋯  │
└──────────────────────────────────────────────────────┘
                                                      │
                                        ⋯ 菜单 ───────┤
                                          职业工具    │
                                          高级模式    │
                                          语言 中/EN  │
                                          它绝不会做什么
```

五个主区域，一层深。没有步骤编号，没有全局流程条，没有子标签堆叠。

| 区域 | 职责 | 一句话 |
|---|---|---|
| 首页 | 一个推荐动作 + 最近活动 | 我现在该做什么 |
| 岗位 | 5 个分桶 + 添加岗位 | 有哪些机会 |
| 申请 | 进行中的申请卡片 | 我手上有什么在跑 |
| 我的资料 | 在线求职档案 + 简历 + 答案 + 定制材料 | 产品知道我什么 |
| 设置 | AI · 岗位来源 · 数据与隐私 · 语言 | 产品怎么工作 |

「职业工具」和「高级模式」只在溢出菜单里，**默认界面不会有任何链接指向它们**。

## 3. 岗位

```
┌──────────────────────────────────────────────────┐
│  [新发现 12] [好匹配 4] [已保存 2] [已申请 7] [已拒绝 3] │
│                                    [ + 添加岗位 ] │
├──────────────────────────────────────────────────┤
│  Epoch AI · 数据科学家                           │
│  上海 · 远程可 · 匹配 82（AI + 规则）             │
│  · 你的 Python 和因果推断经验对得上               │
│  · 要求 5 年，你有 4 年                          │
│                    [ 用 AI 申请 ]  手动申请 ⋅ 保存 ⋅ 不感兴趣 │
├──────────────────────────────────────────────────┤
│  …                                    ‹ 1 2 3 › │
└──────────────────────────────────────────────────┘
```

- 每张卡片**只有一个主按钮**：`用 AI 申请`。其它是次要文字链接。
- 匹配分后面注明来源：`（AI + 规则）` 或 `（规则）`，两者不可比时不并列显示。
- 匹配理由用人话写 2–3 条，不显示评分 JSON、不显示门户名、不显示风险分。
- 每桶独立分页。切桶不丢失滚动位置。
- 「已拒绝」桶里的岗位可以 `重新考虑` 恢复。

```
┌──────────────────────────────────────────────────┐
│  Epoch AI · 数据科学家              需要你（2 项）│
│                                                  │
│  还差 2 项，只有你能做：                          │
│    ○ 附上你的简历                                │
│       已准备好：定制版_EpochAI.pdf               │
│       [ 帮我附上 ]   或者你自己拖进去            │
│    ○ 完成「我不是机器人」验证                     │
│       这一步必须你来，产品不会碰验证码            │
│                                                  │
│  [ 打开页面 ]  [ 我已提交 ]  [ 出了点问题 ]      │
├──────────────────────────────────────────────────┤
│  Anthropic · 研究工程师                  已申请  │
```

- 清单项在每次重新检查后自动消失
- 每一项都说清楚「为什么需要你」

- `出了点问题` → 提供：重新打开页面 / 重新填一次 / 重新开始 / 改成手动。全是人话，不出现「需要恢复」这类词

### 状态词表（用户可见的全部）

```
已找到 · 准备中 · 填写中 · 需要你（N 项）· 可以提交了 · 已申请 · 已保存 · 已拒绝
```

内部 17 个状态、10 个会话状态、包状态、执行器类型，一个都不露出。

```
│                                                  │
```

## 8. 首次运行

```
1  欢迎 → 六条承诺 → [ 开始 ]
2  上传简历 → 解析 → 「确认这 9 项基本信息」（一屏，已预填）
3  「粘贴一个岗位链接，或者稍后再设置搜索」→ 用户贴一个链接
4  岗位卡片出现，带匹配理由 → [ 用 AI 申请 ] → 预备抽屉 → 打开并填写
5  「还差 N 项」→ 用户提交 → [ 我已提交 ] → 🎉 已申请：1
```

顺序是刻意的：URL 导入是首次运行路径（它今天就能用），配置搜索是可选的、往后放。

## 9. 组件规范

| 组件 | 用途 | 规则 |
|---|---|---|
| 确认弹窗 | 有后果的或破坏性的决定 | 必须说明：会发生什么 · 什么不会发生（涉及安全边界时）· 是否可逆 · 具体的主按钮文案（如「删除简历」而非「确定」）。破坏性用危险配色，Cancel 常在，Esc 关闭，焦点起始在较安全的一侧 |
| 抽屉 | 预备申请、添加岗位、定制简历 | 一屏高度，不嵌套抽屉 |
| Toast | 短暂的成功反馈 | 必须同时在页面上留下权威状态；失败**不**用 Toast |
| 内联错误 | 失败 | 就在出问题的那个动作旁边 |
| 常驻横幅 | 重要的持续上下文（如「已更新，可撤销」） | 直到相关状态改变才消失 |
| 状态区 | 异步状态变化 | `role="status"` + `aria-live="polite"` |
| 清单 | 「还差 N 项」 | 每项说清为什么需要你；完成即消失；不用百分比代替清单 |

**禁止**：浏览器原生 `alert` / `confirm` / `prompt`（`tests/no_native_dialogs.test.mjs` 会拦）。

**禁用控件规则**：任何被禁用的按钮或输入框，必须在**旁边的可见文字**里说明原因 —— 不能只靠置灰，不能只放在 `title` 属性里（Chrome 对 `disabled` 元素不显示 tooltip，这是现有界面的实际缺陷）。

## 10. 前端模块划分

零构建，原生 ES modules，`<script type="module">` 直接加载。

```
dashboard/quick/
  index.html                唯一 HTML
  app.mjs                   启动 + 挂载路由
  style.css

  core/
    api.mjs                 fetch 封装、错误归一化、同源保证
    events.mjs              SSE 订阅、重连、快照同步
    store.mjs               集中状态 + 订阅通知
    router.mjs              hash 路由、滚动位置保持

  i18n/
    index.mjs               t() + 语言切换 + 持久化
    zh-CN.mjs               默认
    en.mjs

  ui/
    modal.mjs               确认弹窗
    toast.mjs               成功反馈
    drawer.mjs              抽屉容器
    banner.mjs              常驻横幅
    list.mjs                分页列表
    field.mjs               带徽标的字段编辑器
    checklist.mjs           「还差 N 项」

  views/
    home.mjs
    jobs.mjs
    applications.mjs
    profile.mjs
    settings.mjs
    apply-drawer.mjs        预备抽屉
    resume-draft.mjs        定制简历 diff
    add-job.mjs             添加岗位抽屉
    first-run.mjs           首次运行向导
```

### 编码规则

- 单文件不超过 ~300 行
- **不用 innerHTML 拼字符串** —— 用 `document.createElement` 或 `<template>`
- 状态只在 `core/store.mjs`，视图订阅、不直接互相改状态
- 视图函数返回 DOM 节点，不往全局挂东西
- SSE 优先于轮询；轮询只作为 SSE 失败时的降级
- 所有面向用户的字符串走 `t()`，不做运行时拼接（`t('jobs.count', {n})` 而不是 `t('jobs.found') + n`）

### API 层约定

`core/api.mjs` 必须保证请求从 `http://127.0.0.1:8767` 同源发出 —— 服务端会用 403 `UNTRUSTED_REQUEST_ORIGIN` 拒绝跨源的变更请求。

错误归一化：服务端返回 `{status:'blocked'|'error', code, message, blockers[]}`。界面显示 `message`，**永不显示 `code`**；`blockers[]` 渲染成清单项。

## 11. i18n

- `zh-CN` 默认，`en` 并行维护，两个目录键必须对齐（加一个测试断言键集合相同）
- 语言选择存在 `localStorage`
- 日期用本地格式，不硬编码
- 中文文案不用「点击」「请」这类冗余客套；按钮就是动词短语（「打开并填写」而不是「请点击这里打开」）

## 12. 从旧界面继承的问题（新界面必须避免）

审计里实际观察到的，逐条对应：

| 旧问题 | 新界面的处理 |
|---|---|
| 首页 14,490 px 高、94 个可见按钮 | 每个视图只做一件事，一屏为设计单位 |
| 同一屏上两个事实互相矛盾 | 就绪状态只有一个服务端来源（`buildApplicationProfileView`），界面只做投影 |
| 「审阅 Career Brain」打开一个完全空白的弹窗 | 每个弹窗必须有正文；空态有明确文案和下一步 |
| 禁用按钮把原因放在 `title` 里（Chrome 不显示） | 原因必须是旁边的可见文字 |
| 三套并行进度系统（10 步条 + 章节步骤 + 8 阶段搜索子步骤） | 一个都不要 |
| 每张岗位卡片渲染评分 JSON | 匹配理由 2–3 条人话 |
| 完成动作后被传送到另一个筛选 / 标签页 | 完成动作保持当前上下文和滚动位置 |
| 界面 100% 英文（用户是中文母语） | 默认中文 |
| 「Answers ready ○ / 没有可复用答案」这类前端自己发明的判定 | 前端不发明任何状态，所有判定来自服务端 |
